# 「數學解惑」自訓 AI 計劃書（草案）

> 給協助規劃的 AI（例如 Gemini）閱讀用。專案原始碼：https://github.com/tsaibohau/-ai
> 狀態：規劃中，尚未開始訓練。

---

## 1. 專案是什麼

「數學解惑」是一個**台灣高中數學的教學網站**（純前端，部署在 GitHub Pages），目標是像家教一樣教學生**怎麼想**，而不是只給答案。

和一般 AI 解題的差別（這是「亞洲／台灣考試版」，不是國際通用版）：
- 用台灣課本的用語、定義順序和考卷出題方式（例如小題串聯：第 1 小題是在幫第 2 小題鋪路；情境名詞如「村莊、學校」只是包裝，數學上就是「點」）。
- **引導式教學**：老師先問，從學生的回答找出卡在哪裡，再用**淺白、不牽強的比喻**讓學生懂本意（例如：斜率＝爬樓梯，往右一步爬幾階；垂直時斜率相乘 −1＝把手機轉 90°）。
- 每一題都有圖解。

## 2. 目前的架構（已完成）

| 部分 | 做什麼 | 有沒有用 AI |
|---|---|---|
| 解題引擎 | 精確計算（分數、根式、直線、外心等），產生每一步的數字與圖 | 沒有，純程式 |
| 定義樹 | 概念之間的先後關係（從國小、國中到高中），分「要背的定義」和「導出的結論」 | 沒有，人工整理 |
| 對話劇本 | 每一步的引導問題、可能的回答、對應的卡點與比喻 | 沒有，人工撰寫 |
| 聽懂學生的話 | 學生打字回答時，判斷他的意思最接近劇本裡哪一個選項 | **目前是關鍵字比對**；可選用瀏覽器內的開源小模型（Qwen2.5，透過 WebLLM） |

**原則（不能改）**
1. 數字一律由解題引擎計算，AI 不能自己算數學。
2. AI 的輸出不可以有 LaTeX 或 Markdown 符號。
3. **零費用**：不用付費 API 或付費伺服器。
4. 儲存庫是公開的：不能放金鑰、學生個人資料、學校或出版社的原題。

### 對話劇本的樣子（簡化）

```
老師：想像你們兩個拉著一條繩子，你站在正中間，然後往正後方一直退。你離兩個人還是一樣遠嗎？
  選項 1「一樣遠」          → 答對，繼續
  選項 2「不一樣」          → 卡點：以為離開中點就不等距 → 用「左右對稱」的比喻解釋
  選項 3「不知道」（兜底）   → 同上
學生（打字）：應該不一樣吧
→ 要判斷成「選項 2」
```

## 3. 為什麼要自己訓練

目前「聽懂學生的話」靠關鍵字，學生講法一變就聽不懂，只好請他點選項，對話就不自然。
通用的大模型可以聽懂，但：要錢、要網路、比喻和數字會亂講，而且不懂台灣考試的脈絡。

所以想訓練**自己的小模型**，專門做好一件事，並且能在**手機瀏覽器裡免費執行**。

## 4. 分階段計畫

### 第一階段：「聽懂學生」的小分類模型（先做這個）

- **任務**：輸入「老師的問題＋一個選項」和「學生的回答」，輸出「學生是不是這個意思」的分數；分數都低就回答「聽不懂」。
  - 用這種「兩段文字配對」的做法，以後新增劇本或選項不用重新訓練。
- **模型候選**（都要先確認授權能不能用在 MIT 授權的公開專案）：
  - 小型中文 BERT 類模型（例如 `bert-base-chinese`；或台灣中研院 CKIP 的 tiny 系列，據我所知是 GPL-3.0，要確認）。
  - 多語言的小型句向量模型（例如 `multilingual-e5-small`），也可以先**不訓練、直接算相似度**當基準。
- **訓練資料**：
  1. 從 `data/dialogues.json` 取出每一題的選項。
  2. 每個選項寫出 20～50 種學生可能的講法（口語、錯字、注音文、很短的回答如「嗯」「應該吧」）。可以請 Gemini 協助大量改寫，再由人工檢查。
  3. 負例：故意配錯的選項、和題目無關的回答。
  4. 之後有真實使用紀錄時再加入（見第 6 節隱私規則）。
- **在 Colab 上做**：免費的 T4 GPU 就夠，訓練應該幾分鐘到幾十分鐘。
- **怎麼放進網站**：匯出成 ONNX、量化成 int8，用 transformers.js 在瀏覽器執行；模型檔放在 GitHub Pages 或 Hugging Face（免費）。目標大小 < 50 MB，手機也跑得動。
- **怎麼算成功**：
  - 保留一部分沒看過的講法當考題，選對選項的正確率 ≥ 90%。
  - 「聽不懂」的回答要被正確判斷成聽不懂（不能亂對應）。
  - 和目前的關鍵字比對比較，正確率要明顯比較高。

### 第二階段：會「說老師的話」的小生成模型（之後再說）

- **任務**：在劇本的框架內，用更自然的語氣回應學生、追問，必要時換一個比喻。數字仍由引擎提供，模型只能引用。
- **模型候選**：Qwen2.5-0.5B 或 1.5B Instruct（據我所知是 Apache-2.0，要確認），在 Colab 用 LoRA 微調（例如 Unsloth 或 PEFT）。
- **訓練資料**：劇本展開成的完整對話＋人工挑過的好回應。
- **部署**：轉成 MLC 格式，用目前已經接好的 WebLLM 在瀏覽器執行。
- **安全檢查（程式已有）**：輸出中出現引擎沒給的數字會標示警告；LaTeX／Markdown 會被清掉。
- **怎麼算成功**：數字亂講的比例接近 0；由專案擁有者看 30 段對話，覺得「像老師、比喻不牽強」的比例過半。

### 第三階段：用真實紀錄持續改進

- 收集學生在哪裡卡住（網站已經會記錄「老師的筆記」卡點）。
- 定期把新的講法加入訓練資料，重新訓練第一階段的模型。

## 5. 時程建議

| 週 | 工作 |
|---|---|
| 1 | 在 Colab 跑通「不訓練、直接算相似度」的基準，量出正確率 |
| 2 | 準備第一階段的訓練資料（請 Gemini 協助改寫＋人工檢查） |
| 3 | 訓練分類模型、和基準比較 |
| 4 | 匯出 ONNX、接進網站、手機實測 |
| 之後 | 視第一階段效果，決定要不要做第二階段 |

## 6. 規則與限制

- **零費用**：只用 Colab 免費版、免費的模型託管。Colab 免費 GPU 不保證每次都拿得到，要能在中斷後接著跑（定期把檢查點存到 Google Drive）。
- **隱私**：學生的真實對話**不能放進公開儲存庫**。只能存在擁有者自己的 Google Drive，使用前要經過同意、去除可識別資訊。
- **版權**：訓練資料只用自創或改編的題目，不用學校考卷、補習班、出版社原題。
- **授權**：使用的模型授權必須允許在 MIT 授權的公開專案中使用與散布。
- **擁有者沒有電腦**，只有手機：Colab 筆記本要盡量「一格一格按執行就好」，不需要改程式。
